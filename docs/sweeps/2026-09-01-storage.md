# Storage sweep — 2026-09-01

## Scope and boundary

Swept over the `storage` category: vector databases, indexes, feature stores and versioned data
layers for training, inference and retrieval-augmented-generation data.

## First pass

Sources: GitHub topic search (`vector-database`, `vector-search`, `feature-store`,
`data-version-control`), sorted by stars, cross-checked against PyPI and npm. Predeclared
retrieval cutoff: top 25 repositories per topic by all-time stars, star floor 800, executed
2026-09-01. Every accepted row was verified against the GitHub API and its declared package
registry on the same date.

Result across the categories swept that day (16 candidates total, including `compilers` — see
`docs/sweeps/2026-09-01-compilers.md`) fell short of the 50-75 target Carl had set.

## Second pass

Same day, lower floor per Carl's instruction after the first pass's shortfall. Re-ran the
original four topic searches plus six adjacent angles (embedding store, document store ai,
graph database rag, time series database ml, object storage ml, metadata store mlops), top 30
per query, predeclared retrieval cutoff star floor 250. Every new result at or above the floor
was triaged individually, not bucket-parked. Four accepted: `lakesoul`, `pixeltable`, `lamindb`,
`butterfree`.

Across both passes, `storage` ended with 13 candidate rows.

## Round 2 — 2026-09-02

All 13 rows were triaged and promoted or rejected — see `sources/categories/storage.yaml`'s
comments field for the disposition of each. 12 became head products. `butterfree`
(`quintoandar/butterfree`) was rejected as a dormant ETL framework for feeding a feature store
rather than a store itself, and its row was removed rather than parked.
